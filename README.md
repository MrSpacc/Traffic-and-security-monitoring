# Мониторинг трафика и безопасности

Монитор читает новые строки access.log и auth.log, сохраняет метрики в SQLite и блокирует через UFW источники HTTP-флуда, перебора веб-входа, SSH brute-force, сканирования уязвимых путей и IP, набравшие 50 ответов 403.

Сначала задайте PANEL_PASSWORD в config.py. Также пароль можно передать через окружение:

    sudo env ANTI_DDOS_PANEL_PASSWORD='замените-на-длинный-пароль' python main.py

Панель: http://127.0.0.1:8090

Настройки пути к логу, порога, адреса и порта находятся в config.py. Для доступа с другого компьютера задайте WEB_HOST = "0.0.0.0" и защитите панель firewall или reverse proxy; вход защищён паролем панели.

Если система хранит SSH-события только в systemd journal, укажите файловый журнал sshd в AUTH_LOG_FILE или настройте rsyslog. Перед включением автобана добавьте свои административные сети в TRUSTED_NETWORKS. Защита на сервере снижает прикладной HTTP/SSH-флуд, но не заменяет CDN или защиту провайдера от атак, заполняющих сетевой канал.

Ограниченный тест HTTP-флуда на собственном Nginx:

    python tools/http_flood_test.py http://ВАШ_СЕРВЕР/test --i-own-this-target

Тест отправляет 130 запросов и затем завершается. Запросы должны проходить через тот Nginx, чей access.log читает программа. Не проверяйте так чужие сайты.

Безопасная проверка детектора без сетевой нагрузки:

    python tools/simulate_log_flood.py

Она добавляет в access.log 130 строк от зарезервированного тестового адреса 198.51.100.77. Через несколько секунд в панели появится инцидент http_flood.

## Скорость обновления логов

Новые строки проверяются каждые 0,05 секунды. Журнал последних запросов обновляется каждые
0,25 секунды независимо от общей статистики, которая обновляется раз в 2 секунды.
Это не позволяет медленному пересчёту истории задерживать показ новых запросов.
Преобразования одинаковых временных меток кешируются для ускорения разбора потока.
Запись выполняется пакетами до 500 запросов или до 0,1 секунды чтения,
с сохранением позиции файла в той же транзакции. Незавершённые строки
дочитываются после появления перевода строки; ротация и усечение файла учитываются.

По умолчанию читается локальный access.log рядом с программой. Для рабочего Nginx
задайте LOG_FILE в config.py или переменную окружения NGINX_ACCESS_LOG:

    sudo env NGINX_ACCESS_LOG=/var/log/nginx/access.log python main.py

Обновление начинается после фактической записи строки в файл. Если Nginx пишет
логи с buffer/flush или файл доставляется по расписанию, задержка возникает ещё
до парсера: проверьте настройки access_log и период копирования. Для немедленной
записи используйте access_log без буферизации. После изменения программы
перезапустите её и обновите страницу панели.
